## 2026-03-26 - Sticky Layout Hierarchy & Standard Keyboard Focus Rings
**Learning:** Rendering a `sticky top-0` banner *after* the main scroll container in the DOM tree places it below the page fold by default, which prevents the banner from sticking at the top of the viewport on initial page load. Splitting the app layout shell into dedicated top/bottom layout chrome wrappers (e.g. `AppTopChrome` before `AppRoutes` and `AppChrome` after `AppRoutes`) allows sticky top headers to sit naturally at the top of the DOM flow while keeping layout elements modular. Additionally, styling interactive buttons with `active:scale-95 transition` paired with offset rings (`focus-visible:ring-offset-stitch-bg`) provides delightful, highly accessible touch and keyboard feedback.
**Action:** When implementing sticky header panels, verify they are positioned at the absolute top of the DOM hierarchy relative to scroll containers. Always style interactive elements with standard focus ring offsets to ensure WCAG-compliant keyboard-navigable contrast.
